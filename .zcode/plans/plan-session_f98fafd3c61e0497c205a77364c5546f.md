# `whoson` — live device list + real speed limits via your laptop as a Wi-Fi toll booth

Pure-Python CLI (no pip packages) for Arch Linux, using standard Linux tools (`networkmanager`, `dnsmasq`, `iproute2`'s `tc`, `nftables`, `iw`, `wpa_supplicant` — README lists them with one `pacman` install line).

**Main feature — per-device speed limits** — works by routing chosen devices through your laptop: they join the laptop's own Wi-Fi (`whoson start` creates it), their traffic then flows *device → laptop → router*, and Linux caps each device's download/upload exactly. **Live list** shows both networks: toll-booth clients (instant, authoritative) and router-side devices (asked from the router every 10–15s; door-knocking scanner as automatic fallback).

**The control boundary, labeled honestly**: devices on the laptop's Wi-Fi can be limited and blocked *on that network* — a device can hop back to the router's Wi-Fi to escape. The UI says "blocked on whoson" vs "blocked at router". README explains the real-enforcement recipe (change router Wi-Fi password, or cable laptop + disable router Wi-Fi) and the OpenWrt second-router alternative for always-on whole-house control.

## Commands

```
whoson                    # live view (default): both networks, self-updating table + event log
whoson start / stop       # toll-booth Wi-Fi on/off (sudo when needed; stop is crash-safe/idempotent)
whoson limit <device> 5/1 # cap 5 Mbps down / 1 Mbps up
whoson unlimit <device>
whoson block <device>     # toll-booth client: firewall drop | router device: router parental control
whoson unblock <device>   #   (labels always say which network the block applies to)
whoson --once / --json    # snapshot / machine-readable
whoson <cmd> --dry-run    # print the exact system commands instead of running them (no root needed)
```

Refuses to limit/block the laptop itself or the uplink router. Table flags: ⛔ blocked, `5/1` capped, `📶` toll-booth client, "Private address" for phones' random MACs (detected via the locally-administered bit; identities merged by hostname; warned that MAC-blocks break if the phone re-randomizes). Joins are instant; out-of-range disconnects can linger minutes — shown and documented honestly.

## Hardening & robustness (from the design review)

- **Laptop isolation**: dedicated nftables table (`whoson`) blocks hotspot→laptop traffic except DHCP and DNS; NAT to the router stays. Teardown = drop that one table + tc setup; `whoson stop` works after crashes (idempotent cleanup).
- **Upload caps** (hardest part: Linux meters outgoing traffic directly, incoming needs an IFB redirect) — explicitly Phase 1's pass/fail item, both directions tested.
- **Router client**: one reused login session, 10–15s polling, error backoff (interval doubles to 60s max), auto-fallback to scanner; router data marked "may lag" (single-admin-session routers, weak CPUs).
- **All system commands generated by pure functions** → `--dry-run` → unit tests need no root.

## Steps (priority order: limits first; every step has a pass/fail)

1. **Go/no-go (2 min)**: parse `iw list` valid interface combinations for managed+AP. Your chip is an Intel AX200 (confirmed from system files) — known to support it with same-channel sharing (~halved relay throughput, brief drops if router changes channel; documented; cable or USB-AP adapter presented as the often-better alternative).
2. **Prove the hotspot by hand**: two plain `nmcli` commands, phone joins, internet works through the laptop — before any Python is written around it.
3. **Phase 1 — toll booth (main feature)**: `cmdgen.py` pure command generators + tests first, then `gateway.py` (hotspot up/down, instant client list via station/lease state, download+upload caps via tc+IFB, block via nft drop). **Live proof with your phone: join → speed test shows ~5/1 → uncap → full speed restores → leave, with instant list events.** No router dependency at any point.
4. **Phase 2 — router integration**: discover WE firmware's real login / Connected Devices / parental-control pages (captured as fixtures, parser written against reality), merge router devices into the live view (10–15s, backoff, fallback to scanner), add router-side block/unblock.
5. **Finish**: full `python3 -m unittest` green, `pipx install .`, README with glossary and honest limitations.

Honesty commitments: no guarantees — each phase is built to fail fast and cheaply if reality disagrees; worst case for router-side features is degradation to the scanner, never loss of the toll-booth feature; every user-facing message explains network terms in plain words.
